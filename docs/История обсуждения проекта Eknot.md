# История обсуждения и разработки проекта Eknot

Дата подготовки: 23 ноября 2026 года. Основная работа, описанная в переписке, выполнена 20 ноября 2026 года.

Документ составлен по истории чата. Он разделяет первоначальные планы, выполненную работу и дальнейшие задачи. Указанные результаты пробных запросов относятся к моменту проверки и могут изменяться в источнике.

## 1. Первоначальная задача

Пользователь предложил разработать сервис, который собирает сведения о жилых комплексах и жилых домах Астаны и формирует базу данных. В начале обсуждения папка `D:\Eknot` была пустой.

В качестве источников были выбраны 2ГИС и Krisha.kz. Предполагалось сначала получать и хранить данные каждого источника отдельно, а затем сопоставлять объекты и объединять информацию.

Пользователю были нужны максимально полные сведения:

- название ЖК, адрес, район и координаты;
- количество квартир, этажей, подъездов и лифтов;
- застройщик, год постройки, статус строительства и сроки сдачи;
- тип дома, материал, класс жилья, высота потолков и отделка;
- отопление, парковка, безопасность и инфраструктура;
- организации, работающие внутри зданий;
- рейтинги, отзывы и упоминания проблем;
- другие параметры, опубликованные в источниках.

## 2. Подготовка технического задания

Перед реализацией пользователь попросил сначала составить ТЗ и список полей. Было подготовлено подробное описание сервиса: цели, структура объектов, состав данных, сборщики, хранение, обновление, объединение и критерии приёмки.

При проектировании договорились различать ЖК, очередь строительства и отдельный дом или корпус. Один ЖК может иметь несколько адресов, разную этажность и разные сроки сдачи. Сведения обо всём комплексе нельзя автоматически переносить на каждый корпус.

Также были определены следующие принципы:

- сохранять источник и дату получения данных;
- хранить исходные ответы для проверки и повторной обработки;
- не заменять отсутствующее значение нулём;
- различать общее количество квартир и количество квартир в продаже;
- различать плановую сдачу и фактический ввод в эксплуатацию;
- не считать бизнес рядом с домом бизнесом внутри здания;
- не представлять жалобу из отзыва как установленный дефект;
- при объединении учитывать адрес, название, координаты и состав корпусов;
- спорные совпадения оставлять для ручной проверки.

## 3. Планирование на пять дней

Пользователь пояснил, что проект нужен для отчёта и работу необходимо распределить на несколько дней. Был предложен первоначальный план:

| День | Содержание работы | Ожидаемый результат |
|---|---|---|
| 1 | Анализ источников, проверка доступа, список полей и проектирование базы | Архитектура и структура проекта |
| 2 | Разработка сборщика Krisha.kz | Сбор характеристик на небольшой выборке ЖК |
| 3 | Разработка сборщика 2ГИС | Получение зданий и организаций внутри них |
| 4 | Нормализация и сопоставление источников | Объединённые карточки и проверка спорных совпадений |
| 5 | Тестирование, экспорт и демонстрация | Рабочий прототип и материалы для отчёта |

Это был план, а не перечень уже выполненных дней. Порядок реализации затем изменился: первым начали разрабатывать 2ГИС. Позже пользователь попросил временно убрать Krisha.kz. Объединение источников не реализовано.

## 4. Обсуждение устройства сервиса и бюджета

Было объяснено, что сервис запускается на компьютере или сервере, получает данные из источников, обрабатывает их и сохраняет в базе. Браузер используется для управления и просмотра результатов, а сам сбор выполняется сервером.

Первоначально обсуждались Python, FastAPI, PostgreSQL и простой веб-интерфейс. После уточнения, что бюджет составляет 0 ₸, выбрали более простую локальную конфигурацию:

| Компонент | Реализованный вариант |
|---|---|
| Язык | Python |
| Серверное API | FastAPI |
| Запуск сервера | Uvicorn |
| HTTP-запросы | HTTPX |
| База данных | SQLite |
| Настройки | `.env` и переменные окружения |
| Управление | Интерактивная документация Swagger UI по адресу `/docs` |

Отдельный пользовательский интерфейс, PostgreSQL и автоматическое расписание пока не реализованы. Сервис работает локально, пока запущен процесс сервера.

## 5. Выбор способа доступа к 2ГИС

Пользователь спрашивал, будет ли кнопка сбора получать данные всей Астаны и можно ли бесплатно брать сведения непосредственно с сайта 2ГИС.

В обсуждении уточнили, что полный обход города требует отдельного механизма охвата территории, обработки пагинации и ограничений выдачи. Поиск по одной фразе не является полным реестром всех домов.

Был рассмотрен парсинг сайта, но затем пользователь выбрал официальный API. Для начала использован демо-ключ 2ГИС. По проверенной документации демо-доступ ограничен сроком действия и количеством запросов; постоянный бесплатный сбор всего города не был подтверждён.

Ключ хранится локально в `.env`. Пользователю было объяснено, что `TWOGIS_CITY_ID` и `TWOGIS_EXTRA_FIELDS` можно сначала оставить пустыми. Астана определяется автоматически, а дополнительные поля подключаются после проверки доступа.

## 6. Реализация сборщика 2ГИС

С нуля создан локальный сервис со следующими возможностями:

- поиск зданий Астаны по запросу пользователя;
- получение организаций по ID конкретного здания;
- получение рейтинга и счётчиков отзывов при наличии в API;
- фоновое выполнение заданий;
- ограничение страниц и количества запросов;
- сохранение контрольной точки и продолжение сбора;
- сохранение исходных ответов и времени получения;
- обновление записей без создания дубликатов;
- просмотр объектов через API;
- экспорт JSON и CSV;
- обработка ошибок доступа, сети и неожиданного формата ответа.

База размещена в `data/eknot.sqlite3`. Основные таблицы действующего сервиса — `jobs`, `source_objects` и `snapshots`.

### Основные методы API

| Метод | Назначение |
|---|---|
| `GET /api/status` | Состояние сервиса и наличие настроенного ключа |
| `POST /api/2gis/jobs` | Создание задания сбора |
| `GET /api/jobs` | Список заданий |
| `GET /api/jobs/{job_id}` | Состояние конкретного задания |
| `POST /api/jobs/{job_id}/resume` | Продолжение задания |
| `GET /api/objects` | Просмотр сохранённых объектов |
| `GET /api/objects/{source_id}` | Детальная запись объекта |
| `GET /api/export` | Выгрузка JSON или CSV |

В запросе задания задаются тип сбора, поисковая фраза либо ID здания, максимальное количество страниц и запросов. Статус `limited` означает достижение установленного лимита, а не обязательно ошибку. Статус `completed` относится только к выбранной поисковой выдаче.

## 7. Запуск и исправление обнаруженных ошибок

Пользователь запускал сервис через Windows CMD. Для перехода с диска C: на диск D: была уточнена команда `cd /d D:\Eknot`.

```cmd
cd /d D:\Eknot
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В процессе были обнаружены и исправлены следующие ситуации:

1. **Порт 8000 был занят.** Причиной оказался тестовый сервер, ранее запущенный во время разработки. Он был остановлен.
2. **Ответ 409 при повторном запуске сбора.** Сервис уже выполнял задание и блокировал второе. Пользователю объяснили, как смотреть статус через `/api/jobs`.
3. **Не определялась Астана.** Код ожидал `type: adm_div.city`, а реальный ответ содержал `type: adm_div` и `subtype: city`. Обработка исправлена и добавлена проверка тестом.
4. **Пустой поиск организаций.** Сочетание фильтров `city_id` и `building_id` давало пустой результат в проверенных запросах. Для организаций оставлен фильтр здания без дополнительного фильтра города.

После изменения кода или `.env` пользователю рекомендовано перезапускать сервер через Ctrl+C и повторную команду запуска.

## 8. Результаты реальных проверок 2ГИС

В пробном сборе были сохранены 10 зданий. В числе полученных названий — Айналайын, Арлан, Atlant, Gamma, Данияр, Восток, Виктория, Сарайшык, Аулие-Ата и Коркем.

Для запроса «жилой комплекс» API на момент проверки сообщил о 85 результатах. Это не было объявлено количеством всех ЖК или домов Астаны.

В базовых записях присутствовали название, адрес, ID здания, координаты, административные территории, назначение здания и время получения. Дополнительно встречались код здания и почтовый индекс.

Пользователь прислал выгрузку, после чего было объяснено значение полей `source`, `source_id`, `building_id`, `object_type`, `lon`, `lat`, `collected_at` и `attributes`.

Отдельная проверка дополнительных данных показала:

| Сведения | Результат проверки |
|---|---|
| Название, адрес, район, координаты | Получены |
| Рейтинг и счётчики отзывов | Получены |
| Организации внутри здания | Получены после исправления фильтров |
| Этажность, квартиры, подъезды, лифты, год постройки | Не возвращены для 10 проверенных зданий при явном запросе |
| Тексты отзывов | Не получены; отдельный модуль не реализован |

Для Айналайын API вернул рейтинг 4,3 и счётчик 36 отзывов. Поиск организаций в этом здании сообщил о 22 результатах; первые 10 были сохранены в базу. Среди контрольных результатов по другой записи был магазин Kingsman в доме ЖК «Коркем».

Отсутствие строительных полей не позволяет по одному ответу установить причину: возможны ограничения прав ключа либо отсутствие данных. В документации 2ГИС соответствующие характеристики отмечены как требующие дополнительного доступа. Значения не были выдуманы или заменены нулями.

Результаты проверки доступа сохранены локально в `data/2gis-access-check.json`.

## 9. Временная реализация Krisha.kz и её удаление

После обсуждения недостающих характеристик пользователь попросил начать Krisha.kz. Был создан независимый сборщик открытых страниц без API-ключа: каталог Астаны, карточки ЖК, ограничения запросов, продолжение заданий и отдельное хранение источника.

На реальных страницах были извлечены следующие данные:

| ЖК | Этажность | Количество квартир | Высота потолков |
|---|---:|---:|---:|
| Isma | 9 | 503 | 3,2 м |
| МЖК «Астана» | 3 | 1500 | 2,6 м |
| Swiss Collection Astana | 4–5 | 137 | 3,85 м |

Также извлекались застройщик, класс жилья, тип дома, отделка, отопление, парковка, лифты, статус и сроки строительства, а также другие опубликованные параметры. Характеристики сохранялись с привязкой к комплексу целиком.

После этой работы пользователь изменил текущий объём проекта: «убери пока крышу и оставь только 2гис».

По этому запросу удалены сборщик Krisha.kz, его API-методы, скрипт запуска, зависимости и профильные тесты. Просмотр, экспорт и список заданий ограничены источником `2gis`. Ранее полученные записи Krisha.kz оставлены в локальной базе, но не выдаются действующим API. Объединение источников не выполнялось.

## 10. Тестирование

На разных этапах количество проверок менялось: сначала 7 тестов, после исправления определения города — 8, при наличии Krisha.kz — 15. После удаления Krisha.kz актуальный набор составил **9 успешно пройденных тестов**.

Проверялись продолжение пагинации, отсутствие дубликатов, история ответов, подсчёт лимита запросов, ошибки доступа, определение города, фильтр организаций, экспорт и исключение старого источника из API.

Тесты используют временную базу и подменённые ответы HTTP. Реальные обращения к источникам выполнялись отдельно при пробном сборе.

Пользователь поручил создать новый репозиторий. Проект был подготовлен к публикации, пользователь самостоятельно вошёл в GitHub, после чего создан публичный репозиторий:

Публикация исходников на GitHub не означает размещение работающего сервера в интернете. Сам сервис продолжает запускаться локально.

## 13. Состояние проекта по итогам обсуждения

**Работает:** локальный сервис 2ГИС на Python/FastAPI/SQLite, сбор зданий и организаций, доступная статистика отзывов, задания с лимитами и продолжением, сохранение ответов, просмотр и экспорт. Исходники опубликованы на GitHub.

**Ограничения:** полный обход всех домов Астаны не реализован; отдельного пользовательского интерфейса и расписания нет; тексты отзывов и анализ проблем не подключены; доступ к строительным характеристикам не подтверждён. Лимиты и срок действия демо-ключа сохраняются.

**Отложено по запросу пользователя:** Krisha.kz и объединение источников. Разделение ЖК, очередей и корпусов пока существует как проектное требование, а не завершённый механизм автоматического связывания.
