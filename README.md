# Eknot — сведения о домах Астаны

Локальный Python-сервис с официальным Places API 2ГИС, SQLite
и интерактивной документацией FastAPI.
Оплачивать сервер не требуется.

## Что реализовано

- Поиск зданий в пределах Астаны по запросу пользователя.
- Получение организаций строго по ID здания, а не по радиусу.
- Фоновые задания с ограничением страниц и количества HTTP-запросов.
- Продолжение задания с сохранённой страницы после ошибки или остановки.
- Сохранение всех возвращённых API полей, истории ответов и времени загрузки.
- Защита от дубликатов объектов; экспорт JSON и CSV.
- Сбор, просмотр, задания и экспорт работают только с источником `2gis`.

Это **поисковая выборка**, а не полный реестр всех домов Астаны. Тип `building`
сам по себе не подтверждает жилое назначение: результаты требуют проверки.
ЖК, их корпуса и очереди пока автоматически не связываются. Отдельного
пользовательского интерфейса пока нет; действия доступны через `/docs`.

## Запуск в Windows PowerShell

Рабочая папка: `D:\Eknot`. Требуется Python 3.11 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Для воспроизведения проверенного окружения вместо `requirements.txt` можно
установить `requirements.lock.txt` (снимок версий для текущего Python 3.14).

Последнюю команду выполняйте только при отсутствии своего `.env`, чтобы не
перезаписать настройки. Получите демо-ключ с доступом к Places API в личном
кабинете https://platform.2gis.ru/ и локально заполните файл `.env`:

```dotenv
TWOGIS_API_KEY=ваш_ключ
```

Не отправляйте ключ в чат и не добавляйте `.env` в Git. После изменения настроек
перезапустите сервер.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000/docs. База создаётся автоматически в
`data/eknot.sqlite3`. Сервер предназначен для локального использования:
не публикуйте его в интернете без авторизации. Запускайте **один процесс** без
`--workers` и `--reload`: очередь заданий находится в памяти процесса.

## Первый сбор

1. В `GET /api/status` проверьте `api_key_configured: true`.
2. В `POST /api/2gis/jobs` нажмите **Try it out** и **Execute** с параметрами:

```json
{
  "kind": "buildings",
  "query": "жилой комплекс",
  "max_pages": 2,
  "max_requests": 5
}
```

3. Скопируйте `job_id`; проверяйте `GET /api/jobs/{job_id}`.
4. Посмотрите `GET /api/objects` или `GET /api/export`.
5. Для организаций создайте отдельное задание, используя реальный числовой
   ID здания из результатов:

```json
{
  "kind": "organizations",
  "building_id": "ID_ЗДАНИЯ",
  "max_pages": 2,
  "max_requests": 5
}
```

Замените `ID_ЗДАНИЯ` перед выполнением: принимаются только цифры. Если типовая
фраза не возвращает здания, попробуйте адрес или название конкретного ЖК.
Нулевая выдача по одной фразе не означает отсутствия домов в городе.

Астана определяется дополнительным API-запросом. Если она не определяется
однозначно, укажите подтверждённый `TWOGIS_CITY_ID` в `.env`.

## Статусы и лимиты

- `queued`, `running`: задание ожидает запуска или выполняется.
- `completed`: получена выбранная поисковая выдача, **не весь город**.
- `limited`: исчерпан лимит страниц или запросов.
- `failed`: ошибка доступа, сети, структуры ответа или неполная выдача.
- `interrupted`: сервис остановился до завершения.

`POST /api/jobs/{job_id}/resume` продолжает ограниченное, ошибочное или
прерванное задание. Каждое нажатие выделяет новый бюджет `max_requests`;
счётчик `requests` показывает суммарное число попыток по заданию. Повторы
ошибочных запросов и поиск ID города входят в бюджет. Пока выполняется одно
задание, запуск другого запрещён. Самостоятельного расписания пока нет.

Демо-ключ имеет ограниченный срок действия и лимиты. Программа не подключает
платные подписки и не продлевает ключ. Локальный лимит задания не заменяет
контроль квоты в кабинете 2ГИС.

## Дополнительные поля

По умолчанию запрашиваются адрес, координаты, административные территории
и статистика отзывов (рейтинг и счётчики, когда они возвращаются API);
для организаций — также рубрики и расписание. Остальные возвращённые поля
сохраняются без отбрасывания в `raw_json`, в выгрузке — в `attributes`.

Живая проверка на 10 зданиях: `data/2gis-access-check.json`. На проверенном
ключе рейтинг и счётчики возвращаются, строительные характеристики были
пропущены API. Причину отсутствия поля нельзя установить только по пустому
ответу: возможны ограничения доступа или отсутствие данных. Поиск организаций
внутри здания использует только `building_id`, без дополнительного `city_id`:
сочетание этих фильтров в проверке дало ложную пустую выдачу.

После проверки прав своего ключа можно указать, например:

```dotenv
TWOGIS_EXTRA_FIELDS=items.floors,items.structure_info.apartments_count,items.structure_info.year_of_construction
```

Часть характеристик требует дополнительного доступа. Отсутствующее поле не
считается нулём: оно просто не возвращено API, точная причина может быть
неизвестна. Тексты отзывов и анализ проблем не реализованы. Ключ API и URL
запросов с ключом не сохраняются в базе и сообщениях ошибок.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют временные базы и подменённый HTTP-транспорт. Они проверяют
пагинацию, продолжение, сохранение истории, отсутствие дубликатов, фильтр здания,
лимит запросов, ошибки доступа и API. Это не проверка реального доступа к 2ГИС:
для неё нужен ваш ключ.

## Следующие этапы

1. Проверить реальный API на небольшой выборке Астаны и уточнить доступные поля.
2. Реализовать подтверждённый механизм охвата территории, фильтрацию жилых
   зданий и отчёт о полноте. Не объявлять поисковую выдачу полным обходом.
3. Добавить отчёт о заполненности доступных полей 2ГИС.
4. Добавить связи ЖК → очередь → корпус.
5. Добавить пользовательский интерфейс и обновления по расписанию.
